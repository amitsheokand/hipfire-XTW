Do not port a new Lloyd-style mb4 for dense MQ4. gfx12 already has fused
HFQ4 batch-tile kernels (`*_wmma_gfx12_bt{4,8,12}`) for **gate_up, residual,
and qkvza**, default-on via `HIPFIRE_GATE_UP_BT`. Adaptive maps
`PREFILL_MAX_BATCH=256` → **B=8** (exact two 16×128 tiles). B=12 is exact
only when N % 192 == 0.

`HIPFIRE_GATE_UP_BT` now also accepts `4`/`8`/`12` as a force (plus `0` =
1-acc). Default unset is unchanged.

**pp2520** (2026-08-25, Qwen3.8-27B MQ4 md5 `129909ad`, n=3, kv q8, noslots,
bins `3fe504cd` / `4986e3a5`, commit `0c039d83` + local selector helper):

| HIPFIRE_GATE_UP_BT | B at N=256 | pp2520 median | vs adaptive |
|---|---:|---:|---:|
| unset (adaptive) | 8 exact | **717.2** | — |
| 12 | 12 partial | 684.4 | **−4.6%** |
| 4 | 4 exact | 635.3 | −11.4% |
| 0 | 1 | 536.0 | −25.3% |

Decode ~36.4–36.5 all arms. Channel `test_wmma_gate_up_gfx12` with BT=12:
6/6 OK.

B=8 is already the production pick. Forcing B=12 at 256 is a partial-tile
loss. 1-acc is a real −25%, so BT itself is load-bearing — just not a
missing mb4.

2026-08-25 on the same fixture: 715.9 → 723.6 (**+1.1%**, wash). See
`gfx12-prefill-chunk192-wash-2026-08-25`. Do not flip the default. Do not
re-add B=16 (Muse residual header spills). FA QKV BT landed the same day
(`gfx12-hfq4-qkv-bt-2026-08-25`): 715.9 → 732.1 (**+2.3%**, keep, no 5% claim).
