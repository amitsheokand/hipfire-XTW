# Radeon AI PRO R9700 (gfx1201 / RDNA4) Runbook

This document covers hardware configuration, baseline benchmarking, and optimization guidelines for the **AMD Radeon AI PRO R9700** (`gfx1201`, RDNA4, 32 GB GDDR6) running on **NixOS**.

---

## 1. Hardware Architecture & Specifications

| Property | Value | Notes |
|---|---|---|
| **Architecture** | RDNA4 (`gfx1201`) | Wave32 native, WMMA matrix cores |
| **Compute Units** | 64 CUs (4096 stream processors) | Dual-issue VALU |
| **VRAM** | 32 GB GDDR6 (256-bit bus) | ~640 GB/s peak memory bandwidth |
| **Peak Matrix Compute** | 1531 TOPS (INT4), ~765 TFLOPS (FP8) | Native WMMA FP8/FP4 support |
| **L2 Cache** | 64 MiB | Fixed 256 B EA request granularity |
| **Host Interface** | PCIe 5.0 x16 (32 GT/s) | Resizable BAR / Above 4G Decoding required |

---

## 2. Declarative Host Tuning (NixOS)

Add the following kernel parameters to your NixOS host configuration (`hosts/nixos/...`):

```nix
boot.kernelParams = [
  # Prevent BACO (Bus Active, Chip Off) sleep state lockups:
  "amdgpu.runpm=0"

  # Eliminate PCIe L1 exit latency overhead (critical for dense decode bandwidth):
  "pcie_aspm.policy=performance"

  # Disable GECC / RAS memory parity check latency:
  "amdgpu.ras_enable=0"

  # Enable full OverDrive, DPM, and voltage/power telemetry access:
  "amdgpu.ppfeaturemask=0xffffffff"
];
```

### Power Profile & Clock Governor Caution
- **Keep `power_dpm_force_performance_level=auto`** for optimal burst performance.
- Locking `power_dpm_force_performance_level=high` clamps clocks to the top entry in the discrete DPM table (**2350 MHz**), preventing the GPU from opportunistically boosting up to **~3348 MHz** during prefill/compute phases.

## 3. Stock Baseline Benchmarking

Run fresh-process benchmark sweeps with fixed prompt fixtures:

```bash
# Dense Baseline (Qwen 3.8 27B):
hipfire bench qwen3.8:27b \
  --runs 5 --warmups 3 --max-tokens 128 \
  --backend noslots --workload stateless --json

# MoE Baseline (Qwen 3.6 35B-A3B MQ4R):
hipfire bench qwen3.6:35b-a3b-mq4r \
  --runs 5 --warmups 3 --max-tokens 128 \
  --backend noslots --workload stateless --json
```

## 4. Key Performance Insights & Pitfalls

1. **ASPM Latency on Dense Models:** Setting `pcie_aspm.policy=performance` removes L1 exit latency spikes, yielding up to **+10.8%** higher autoregressive decode throughput on dense models.
2. **Profiling Counter Bug:** Counter-based hardware profiling on gfx1201 returns 0 for `FETCH_SIZE` in ROCm tools due to the hardware's 256 B EA request size. Use **PC sampling** (`ROCPROFILER_PC_SAMPLING_BETA_ENABLED=ON`) for true kernel disassembly attribution.
3. **Prefill Batch Sizing (`-ub 2048`):** For hybrid GatedDeltaNet architectures (Qwen3.5/3.6/3.8), micro-batch sizes $\ge 2048$ prevent register wave-boundary dispatch stalls.
